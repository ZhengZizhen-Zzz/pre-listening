## 做好了 PPT，不等于准备好了汇报

答辩、课程汇报或方案评审就在眼前。材料准备好了，试讲却总超时；删了背景又怕重点没讲清；朋友说“有点乱”，自己仍不知道从哪句改起。回听录音、对照页码、把建议搬回讲稿，又是一轮整理。

**Pre 优先服务“已有材料、还没练熟”的汇报者，帮助完成一件事：找到最值得改的一段，把修改带进下一遍演练。** 有讲稿可以直接导入，没有逐字稿可以先讲一遍。表达熟悉后，再用同一份材料准备听众追问。

| 试讲中的困难 | Pre 如何帮助 | 用户得到的下一步 |
| --- | --- | --- |
| 超时，却不知道哪里值得压缩 | 将逐页用时与实际原话关联，提出有依据的取舍 | 选择保留内容，改一段，再练核对时间 |
| 建议看着有道理，不知道怎么用 | 同屏看 PPT、原话与建议稿，修改后再采用 | 更新对应页练习稿，原始内容保留 |
| 讲熟了，但一追问就卡住 | 根据材料与发言准备 3–10 题，保存每题评价要点 | 回答、点评、改写，再按同一标准重答 |

## 为什么用 Pre，而不直接找通用 Agent 练习？

**Pre 把“这一页实际讲了多久、哪句话值得改、改完下一遍怎么练”连成一套现成体验。** 用户在网页里正常翻页、试讲，系统记录过程；复盘中的修改可以直接进入对应页讲稿，再带回下一轮演练。

| 同一场汇报要完成的事 | 将 PPT / 录音交给通用 Agent 对话 | 在 Pre 中演练 |
| --- | --- | --- |
| **找出时间花在哪一页** | 仅有 PPT 和录音，缺少确切翻页时刻；需要另行记录、提供或接入计时工具 | 演练时同步记录网页翻页，统计每页实际停留时间，包含停顿和回翻 |
| **把建议用进下一遍** | 得到改稿后，还要将其整理回自己的逐页讲稿，并管理原稿与修改版 | 对照 PPT、原话和建议稿，采用后更新对应页练习稿，原始内容保留 |
| **核对这一遍是否有改善** | 需要再提供前后两轮材料、计时与目标，组织比较依据 | 在同一材料和目标下关联独立新录音，比较实际用时，再由用户确认重点是否保留 |

**用户减少的是额外计时、标注页码、搬运改稿和整理前后版本的工作。** 比较口径是未额外接入翻页计时与演练管理工具的通用对话；通用 Agent 通过工具也能扩展这些能力，Pre 将它们预先整合进汇报练习流程。[查看场景对照与设计依据 →](docs/PRODUCT.md#与通用-agent-的差异落在演练过程)

## 修改不是终点，下一遍才是

```mermaid

  A[导入材料 / 已有稿件] --> B[试讲与逐页计时]
  B --> C[核对发言与复盘]
```

## 一条真实反馈，如何同时验证价值与暴露阻力

一位试用者在提交的复盘中，将“个人经历的转折关系不清”和“故事主体不明确”两条建议都标为**判断正确、愿意采用**，并反馈对下一次演讲有帮助。同时，用户提出 PPT 预览太小，无法方便地核对内容。

这条反馈支持了“具体到原话的建议有价值”，也提醒我：建议必须方便核对，并能进入下一版讲稿。因此，迭代持续围绕 **PPT 直接可见、原话与改稿靠近、采用后明确更新位置** 展开。

记录中已有两份建议稿，但没有确认采用时间或下一轮数据；“愿意采用”与“实际改善”分开记录。[查看匿名案例、证据状态与后续验证计划 →](docs/USER-CASE.md)

## 从想法到产品，我做了什么

我发起并主导 Pre聆听大师，从需求梳理、交互设计到试用验证与持续迭代，使用 AI 编程工具完成可运行的 Web 产品。推进过程中，我重点做了以下几项决策：

- **定义优先任务：** 从有无讲稿、是否练熟梳理准备状态，优先打通“试讲—定位问题—改稿—再练”；将任意 PPT 排版编辑留在当前范围之外。
- **制定 AI 判断边界：** 根据亲自试用中的误判，明确同义转述可以保留、转写错误不能归责演讲者、改稿不能补造事实；推动 Prompt、证据校验与回归用例一起调整。
- **推动反馈落地：** 汇总朋友试用中等待、录音中断和操作困惑，调整优先级；以首个可用结果、恢复能力、采用后的内容去向验收，而非只检查功能按钮是否存在。

## Agent 决定下一步，Harness 约束它能做什么

在原有流程中加入有边界的目标 Agent。例如“讲进 5 分钟，同时保留研究方法与当前进度”：读取计时证据后，模型在**诊断、压缩、澄清、再练、请求完成确认**之间选择动作。用户要求保留某段，会成为后续约束；已有可用结果则直接复用。

| 围绕目标推进的一步 | 产品中的职责 |
| --- | --- |
| **读取证据** | 通过 MCP 读取计时摘要，结合当前材料、发言和目标判断条件是否充分 |
| **选择动作** | 模型在诊断、压缩、澄清和再练之间作选择；代码检查动作条件与引用依据 |
| **承接取舍** | 用户决定采用或保留，采用的修改进入练习稿，保留要求成为后续约束 |
| **检查目标** | 新一轮演练核对实际用时；重点是否讲清交给用户确认 |

已有可用建议直接复用；录音尚未完成时先补全输入。需要语义判断时才调用模型，减少重复规划。[模型决策、工具观察与校验过程 →](docs/AGENT-TRACE.md)

Harness 包括原话校验、独立语义复核、事实保持、动作白名单、调用预算和恢复机制。MCP 提供指定页上下文与计时摘要；上传、录音、保存仍由确定性代码完成。[架构与实现位置 →](docs/ARCHITECTURE.md)

## 体验与验证

需要 **Node.js 22+**。不配置模型密钥也能运行「查看示例」，体验预设演练与改稿流程。

```bash
git clone https://github.com/ZhengZizhen-Zzz/pre-listening.git
cd pre-listening
npm ci
cp .env.example .env
npm start
```

打开 `http://127.0.0.1:3210`。真实诊断使用配置的文本模型，语音识别使用百炼；完整 PPT 转换另需 LibreOffice。[安装与配置 →](docs/SETUP.md)

公开版基线通过 **302 项自动化测试**，附 **29 条合成评估输入**，覆盖证据、事实保持、恢复、隔离与目标决策。模型实测、浏览器链路和当前适用边界分别记录，便于复现与持续迭代。[测试范围与验证记录 →](docs/VALIDATION.md)
