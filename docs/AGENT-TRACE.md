**合成输入，真实模型，实际执行。** 本页公开结构化动作、工具结果、校验结果与失败状态，帮助区分模型决策、确定性工作流和人工确认。

## 这组记录怎样产生

2026-10-14，使用公开仓库中的 `GoalAgentRuns`，调用真实 DeepSeek 服务与实际本地 MCP 子进程。模型配置及响应均为 `deepseek-flash`，Agent 版本为 `goal-agent-2026-10-13.3`。

输入为虚构的“自习座位研究计划”汇报。材料、发言、420 / 280 秒计时及录音 ID 全部由[固定测试输入](../evals/goal/fixtures.json)构造，**没有真实录音或真人表现测量**。这组验证检验决策与执行逻辑，不检验录音、ASR 或改善效果。

没有替换模型返回，没有模拟 MCP，没有为了截取成功结果反复重跑。四种状态各执行一次，总计 7 次文字模型网络请求；其中包含压缩工具内部的有限修复调用。原始结构化动作和失败结果均保留；没有存储凭证或模型内部推理内容。

## 同一个目标，四种不同状态

目标：**把汇报控制在 5 分钟内，保留研究方法与当前进度：计划访谈 5 名同学，目前尚未开展访谈。**

| 输入状态 | 谁决定了什么 | 实际结果 | 模型请求 |
| --- | --- | --- | --- |
| 本轮尚未结束 | 代码检查完整性，要求先完成录音 | `clarify`，没有调用模型 | 0 |
| 完整输入 420 秒，目标 300 秒 | 模型读到超时 120 秒，选择 `compress` | 压缩结果及一次修复未通过引用校验，任务 `failed`，没有可用方案 | 3 |
| 同样超时，但所有段落都要求保留 | 模型仍选择 `compress`，未先澄清取舍 | 压缩结果及一次修复未通过引用校验，任务 `failed` | 3 |
| 独立新轮次输入 280 秒，重点原话仍在 | 模型选择 `complete` | 程序转为 `confirm`，请求用户确认重点 | 1 |

`complete` 作为任务状态，只表示本次程序执行已结束；它与模型的 `complete` 动作、用户最终确认目标完成，是不同的概念。

## 展开一条：为什么达标后停止继续改稿

**1. 程序先调用工具。** `get_timing_summary` 返回 280 秒、目标 300 秒、超时 0 秒；比较逻辑确认测试输入中轮次与录音 ID 不同、材料与目标相同。工具调用由代码安排，不是模型临时选择。

**2. 模型读取工具观察与当前发言，再选择动作。** 这次返回的结构化结果包括：

```json
{
  "action": "complete",
  "message": "当前完整录音280秒，已在5分钟内；研究方法与进度均有原话覆盖，请确认是否按此定稿。",
  "evidence": [
    {
      "segmentId": "s2",
      "quote": "我们计划访谈5名同学，了解他们寻找自习座位的实际经历。目前尚未开展访谈，所以这里介绍的是研究计划，还不能给出研究结论。"
    }
  ]
}
```

以上摘录保留了一条依据；完整输出还引用了背景段落，见 JSON 的 `runs[id=within-limit].decisions`。

**3. Harness 核对条件和原话。** 检查本轮完整、具备录音标识、计时可靠且没有超时，逐字核对引用属于当前发言。通过后将模型的 `complete` 转为 `confirm`，交给用户判断重点是否讲清。没有再调用诊断或压缩，也不要求把 280 秒硬凑到 300 秒。

**4. 保留测量边界。** JSON 中的 `deltaSeconds=-140` 是对合成输入的计算结果，不是真人节省了 140 秒。服务端逻辑接受调用方提供的会话元数据；本次记录不能证明计时来源不可伪造。

这条记录体现的能力是：结合目标与已有证据，在条件满足时停止追加工作，并保留人的最终判断。

## 失败路径同样进入迭代

超时样本中，模型确实选择了压缩。工具执行时的候选未能通过 `validateTimePlan`，一次修复仍未通过，最终停止展示。记录包含具体失败阶段与错误提示，但未保存这两次压缩候选的原始正文，因此**不能仅凭本记录进一步断言究竟是哪一处引用或格式不合规**。

在“所有段落都要求保留”的输入中，模型也选择了压缩。这没有达到优先澄清取舍的理想行为。由于后续引用检查先失败，本次执行没有走到保护段落过滤阶段，不能把它当成那一层防护已通过真实模型验证。

由此得到两项明确改进任务：

1. 将压缩校验的具体失败类型提供给有限修复，并增加可定位的脱敏诊断记录，减少笼统失败与无效重试。
2. 在全部内容受保护、没有可行动空间时尽早转入澄清，避免让模型继续尝试压缩。

本轮文档更新保留这些发现，未改动朋友正在使用的服务。**拦住不合规结果证明约束起了作用，但任务仍然失败；不能将“被拦截”计为成功交付。**

## 这部分为什么属于 Agent，又有哪些工作交给代码

| 职责 | 实际承担方 |
| --- | --- |
| 记录录音、翻页、存储；检查条件；复用已有方案 | 确定性工作流 |
| 结合目标、保留约束、当前发言及工具观察，选择语义动作 | 受动作白名单约束的模型决策 |
| 执行诊断 / 压缩；检查引用、次数、超时；保护原始数据 | 工具与 Harness |
| 判断建议是否合适、是否采用、重点是否仍保留 | 用户 |

完整模块最多允许 3 次决策；每种诊断 / 压缩动作最多执行一次，工具内另有受限修复。已有可用建议时，代码可直接进入再练，无需模型再说一次“请再练”。因此它是已有产品中的有限目标决策模块，不承担上传、录音等全部流程。

## 复现与审阅

先离线检查输入，不调用模型：

```bash
node scripts/record-goal-trace.mjs
```

配置 `.env` 后，明确开启真实调用并设置总上限：

```bash
node --env-file=.env scripts/record-goal-trace.mjs \
  --live --max-model-calls 8 --output .local/goal-trace.json
```

运行会使用自己的模型账户。失败仍写入结果文件，并返回非零退出码；重新运行的动作与耗时可能变化。脚本不会改动现有演练、自动发布记录或提交真实用户材料。

- [完整执行记录](evidence/goal-agent-live.json)：输入、工具观察、模型动作、校验后动作、调用数与执行状态。
- [可复现输入](../evals/goal/fixtures.json)：所有文本与时间均为合成。
- [执行脚本](../scripts/record-goal-trace.mjs)：直接调用产品实现，记录中附关键源码 SHA-256。
- [自动化回归](../test/goal-agent.test.mjs)：覆盖受保护内容、非法动作、虚假新轮次、取消与调用控制；可控返回测试不替代真实模型实测。

这是一组机制验证记录，不提供成功率、平均延迟或用户收益百分比。
