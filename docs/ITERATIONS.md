# 从试用中的阻力，到下一版的设计

以下内容来自开发过程中的作者试用与外部试用反馈，已归纳转述并去除身份和材料内容。它们说明问题如何推动决策，不代表统计调查或已证明的效果提升。版本按问题主题整理，不伪造发布历史。

先看一个可核对的[真实用户案例](USER-CASE.md)，以及[我在六项关键决策中的具体贡献](PRODUCT-DECISIONS.md)。主题迭代与单一用户的行为证据分开呈现。

## 01 · 建议“严格”，不代表建议正确

**观察：** 用户换一种自然的说法，被判为与 PPT 不一致；口头补充也被要求写回幻灯片。

**判断：** 把材料当标准答案，会破坏正常汇报方式。模型需要理解三种来源：材料内容、实际发言、汇报目标。

**改动：** Prompt 明确允许同义转述与补充；核对全场上下文；引用真实存在后再做独立语义复核。材料与发言冲突时展示成对证据并澄清，不默认 PPT 永远正确。

**验证：** `test/quality-eval.test.mjs`、`test/providers.test.mjs`、公开合成评估集。还需真实用户判断建议是否值得采用。

## 02 · 识别错误不能成为对人的批评

**观察：** 人名、术语识别错误进入复盘，被当作口误或含混表达。

**改动：** 增加术语辅助识别；保留转写核对与回听；文本模型明确没有听到原音频，不从 ASR 文本推断发音问题。转写失败可直接手填和编辑，不把用户困在重试按钮旁。

**验证：** `test/transcript.test.mjs`、`test/transcription-recovery.test.mjs`。ASR 字错率只在人工回听确认的参考文本上计算；没有真值不公布识别准确率。

## 03 · “再等一下”解决不了等待

**观察：** 材料转换久、页数多时难浏览，用户还未开始演练就流失。模拟提问也出现长时间空白。

**改动：** 本地 PPTX 首屏预览、分块上传与后台转换、预览缓存、延后非关键读取；首道问题由本地材料构造起始题，后台补全后续题。已经校验过的方案直接复用，不为了 Agent 外观重复调用模型。

**边界：** 首屏预览不等于完整保真转换；旧版 PPT、复杂媒体、弱网仍可能慢。首题也不冒充实时模型生成。

**验证：** `test/pptx-first-pages.test.mjs`、`test/opening-question.test.mjs`、`test/question-jobs.test.mjs`、`test/analysis-cache.test.mjs`，以及浏览器首屏和完整结果的分别测时。

## 04 · 讲到一半中断，应该能够接着讲

**观察：** 手机中断后只能重来；刷新、转写失败容易让用户怀疑录音是否丢失。

**改动：** 录音前检测；分段保存；中断后恢复；续录时间与翻页偏移衔接；转写任务可继续查询，网络恢复不重复提交付费请求。缺失翻页记录时保留待分配发言。

**验证：** `test/microphone-check.test.mjs`、`test/recording-parts.test.mjs`、`test/recording-guard.test.mjs`、`test/transcription-jobs.test.mjs`。自动化恢复通过不等于所有手机后台策略均已覆盖。

## 05 · 有很多功能，却不知道下一步

**观察：** 用户不理解“核对发言”的作用，也不清楚采用建议后发生了什么；提示、折叠区和重复按钮占据太多空间。

**改动：** 材料与演练按顺序排列；PPT 与建议 / 问题直接可见；原话与建议稿靠近；弱化高级操作；采用后更新练习稿并给出再练入口。感谢反馈等辅助文案不再抢占主要操作区域。

**判断：** 简洁不等于把全部内容折叠。必要的证据和下一步应直接可见，不常用的设置按需出现。

## 06 · 有原稿的人，不应重新复制一遍

**观察：** 用户已经准备了讲稿，或 PPT 中已有备注。

**改动：** 导入 DOCX、文本 PDF、TXT；提取 PPT 每页备注；辅助分段关联材料；演讲者视图显示原备注与练习稿。保留原稿，关联结果可核对，不把导入稿冒充实际发言。

**验证：** `test/script-import.test.mjs`、`test/pptx-notes.test.mjs`、`test/presenter.test.mjs`。扫描讲稿、复杂排版仍有识别限制。

## 07 · 从“报告结束”，走到“目标继续”

**观察：** 用户知道超时，却仍要自己决定先处理哪一段、哪些内容不能删。

**改动：** 保留原工作流，加入有边界的目标 Agent：读取证据 → 选择动作 → 接受内容取舍 → 更新练习稿 → 下一轮验证。优先复用现有方案；不可确认的目标先澄清。

**验证：** `test/goal-agent.test.mjs`、`test/goal-core.test.mjs`。同一录音改字不能当新一轮；不足以比较时不宣称改善；用户选择保留后不重复推送被拒绝的片段。

## 仍在验证的事

2026-10-14 补录的[真实模型决策记录](AGENT-TRACE.md)暴露了压缩结果有限修复后仍失败、全部内容受保护时仍尝试压缩的问题。已保留失败样本与下一步修复方向；本轮公开展示更新未声称已完成这些修复。

功能连通与需求成立是两回事。当前能够证明问题被识别、机制已实现、若干路径可复现；还不能证明用户普遍愿意长期使用或效果优于所有通用 AI。下一步优先做同任务对照、采纳后重练观察与真实设备弱网测试，不以新增功能数量代替产品价值。
