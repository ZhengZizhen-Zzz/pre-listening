# 把“再练一遍”变成可执行的改进

## 从一个具体时刻出发

正式答辩、课程汇报或项目评审临近。用户已有材料，却不确定自己能否在规定时间内讲清楚重点。单独改 PPT 解决不了口头表达；录音回听又需要自己逐页找问题。Pre 将材料、实际发言与时间连接起来，让这一轮的证据直接进入下一轮练习。

产品工作的基本单位是一场有材料、有听众、有时间目标的汇报，而不是一次泛化聊天。核心任务是：**让我知道先改哪一处，改完以后怎样练，并能检查是否有改善。**

## 用户准备状态与优先级

| 准备状态 | 最需要的帮助 | 当前优先级与理由 |
| --- | --- | --- |
| 没有逐字稿，还没练熟 | 先讲一遍，将实际表达整理为可修改的练习稿 | P0：从材料到口头表达的第一步最缺支撑；转写、核对和讲稿衔接是基础链路 |
| 有讲稿，还没练熟 | 导入原稿，按正式节奏试讲，找冗余和衔接问题 | P0：保留已有准备成果，避免重复复制与重写 |
| 有讲稿，已经练熟 | 做信息取舍，准备追问 | P1：压缩与模拟听众问题 |
| 没有逐字稿，已经练熟 | 保留自然说法，检查冗余并练问答 | P1：不过度逐字规范表达 |

这是根据问题强度、完成闭环的依赖和试用反馈做的优先级判断，并非代表性调查得出的市场分布。紧邻正式汇报、有具体截止时间的用户应优先招募验证。

## 场景分类：听众决定需要讲清什么

| 场景 | 听众关心 | 更适合的表达 | 复盘重点 |
| --- | --- | --- | --- |
| 课程汇报 / 答辩 | 论点、方法、依据、局限 | 解释清楚，区分假设与结果 | 逻辑衔接、证据范围、方法追问 |
| 项目进展 / 方案评审 | 进展、风险、方案取舍、下一步 | 结论明确，行动具体 | 信息主次、时间分配、决策条件 |
| 竞选 / 个人展示 | 相关经历、主张、承诺 | 保留个人风格，以实例支持 | 避免经历堆砌，回应具体听众 |
| 科普 / 分享 | 概念是否听懂、例子是否贴切 | 允许类比、转述和口头补充 | 降低理解门槛，避免术语堆积 |

不会把所有 PPT 都套成岗位面试，也不会将“没有逐字念幻灯片”视为缺点。

## 没有工具时，用户如何解决

1. 在 PPT 或笔记软件里写提纲 / 讲稿。
2. 开手机录音或计时器试讲，凭印象判断超时和卡顿。
3. 回听录音，手动对应页码，把想改的句子摘出来。
4. 找朋友提意见，或把材料和文字发给通用 AI。
5. 在原稿中逐处改，再试一次；前后差异通常靠主观记忆。

产品减少的是反复整理上下文、定位证据和把建议搬回练习过程的成本。通用 AI 也能分析讲稿、生成问题；Pre 的差异来自持续记录同一场汇报的页码、时间、原话、采用结果与下一轮，而不是宣称通用模型做不到这些判断。

## 核心设计取舍

**先练，再决定怎么改。** 已有稿件可以导入；没有稿件直接试讲。准备状态不做冗长问卷，通过当前材料与发言决定可用操作。

**先核对发言，再评价发言。** 人名、数字和专业词可能识别错误。核对框修改的是分析输入；原录音留供回听。没有录音的稿件可以做文本练习，但不能冒充真实语速和逐页用时。

**原话 → 建议稿 → 采用 → 再练。** 引用先可定位，建议才可判断；接受修改不是静默覆盖原稿。演讲者视图让修改结果能直接用于下一轮。

**先提供可用的一小步。** PPTX 先显示支持的本地首屏，完整预览随后补齐；问答先展示有材料依据的本地起始问题，模型继续生成其余题目。既减少等待，也明确预览和预设内容的性质。

**不靠“多挑毛病”证明价值。** 允许没有足够证据支持修改；短片段的判断范围要小，提供继续练习的方向，不把未经核对的不足凑成固定数量。

## 三种闭环

- **用户闭环：** 试讲 → 发现具体问题 → 选择修改 → 更新练习稿 → 重练验证。
- **模型闭环：** 生成候选 → 引用校验 → 语义复核 / 事实澄清 → 展示或拒绝 → 有限重试。
- **产品闭环：** 收到试用反馈 → 确认失败路径 → 调整设计或实现 → 回归与浏览器验证 → 再次试用。

这些机制已存在；它们能否持续提高用户表现，仍需要下一阶段的真实练习数据。

## 下一阶段怎样验证价值

优先观察完整流程的完成率、首个可用结果等待时间、建议采纳率以及采纳后是否再次练习。对“建议正确吗”和“愿意采用吗”分别询问，避免把措辞流畅当成帮助。对比通用 AI 时，给同样材料和任务，记录整理上下文的时间与最终练习完成情况，而非只比较谁输出更长。

当前不扩展自动修改任意 PPT 排版、不做声学情绪打分、不建立泛化招聘能力评分。
