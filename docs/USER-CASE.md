# 一段故事讲清楚了，建议才有价值

**真实试用案例 · 从一次反馈，看见价值信号和完成闭环的阻力。**

[返回首页](../README.md) · [个人贡献与决策](PRODUCT-DECISIONS.md) · [迭代记录](ITERATIONS.md)

## 用户当时遇到了什么

一位试用者用自己的材料完成了一轮演讲，并提交使用感受与附带复盘。材料共 13 页，转写整理为 25 段。故事里讲述个人经历的部分，出现了转折关系不连贯、经历主体不明确的问题。

对用户来说，困难是“我知道自己讲得不够清楚，却很难定位是哪一处让人听不懂”。这是对需求的产品侧归纳，不是用户逐字原话。单纯看到转写文本或得到一句“增强逻辑性”，仍然需要自己找句子、想改法、搬回稿件。

本案例依据 2026-10-10 提交的记录整理。原材料、原发言、身份与私人联系方式不公开；以下仅保留问题类型、用户评价和流程状态。它是一例主动提交的反馈，不能代表全部试用者。

## 产品交付了什么，用户怎样判断

| 环节 | 记录中能核对的内容 |
| --- | --- |
| 定位 | 两条建议均关联到同一页的具体发言片段，分别针对“转折关系”和“故事主体” |
| 调整方向 | 梳理经历的先后关系；明确在讲谁的经历。这里是去标识转述，不是公开原稿 |
| 用户判断 | 两条均标记 `judgment=correct`，即认为判断正确 |
| 采纳意愿 | 两条均标记 `adoption=yes`，即愿意采用 |
| 可修改内容 | 两条都有生成的建议稿，状态为 `draft` |
| 实际采用 | 确认采用时间均为空，保存的练习稿为 0 条；记录不能证明已执行采用 |
| 后续演练 | 此次提交未附可用于对照的独立下一轮记录 |

用户主观反馈，工具找出了故事对象不明确的问题，对二次演讲有帮助；同时提出 **PPT 预览过小，难以看清具体文字**。这两部分同样重要：建议是否有价值，以及核对和使用建议是否顺畅。

## 我的产品判断

**第一，价值落在“可定位、能动手改”的建议。** 用户认可的是具体的理解障碍，不是笼统的分数。因此复盘应该把原话、调整后的表达与对应材料放在一起。

**第二，看到建议只是中间状态。** 这份记录已经出现“愿意采用”，但不能证明修改被带进了下一轮。不能把两个“愿意”算成两次实际采用，更不能推导出表达能力提升。

**第三，材料预览属于核心操作。** 当用户要反复回到上方找 PPT，或看不清原页，再好的建议也难核对。后续预览放大、拖动调整尺寸、建议与材料同屏，回应了这条反馈与其他试用者的同类问题。

## 这条反馈怎样进入产品闭环

| 反馈与阻力 | 设计回应 | 当前证据 |
| --- | --- | --- |
| PPT 太小，核对困难 | 增加大屏查看与可调尺寸；建议、问题处直接显示相关页 | [当前交互截图](PRODUCT-TOUR.md#05-把建议放回原话和材料里判断) |
| 认可建议，仍需将其变成下一遍稿件 | 原话与建议稿靠近；编辑采用后更新对应页练习稿 | [采用后的状态](PRODUCT-TOUR.md#06-采用以后修改有去处)、[改稿校验](../public/revision-core.mjs) |
| 采用后还需要检验 | 下一轮独立演练才进入用时比较；同题重答沿用评价要点 | [目标比较实现](../lib/goal-agent.mjs)、[同题练习](PRODUCT-TOUR.md#08-回答之后知道具体缺在哪里) |

这些设计回应同时吸收了我亲自试用的发现和其他朋友的反馈，不能将全部迭代归因于这一位用户。表中的截图来自虚构演示案例，用于说明当前实现，**不是这位用户的后续结果**。

## 这次验证到哪里，下一步验证什么

已观察到：用户用自己的材料完成演练并主动反馈；对两条具体建议给出正向判断；核对材料存在明确体验阻力。

尚未观察到：点击采用后的完整路径、独立第二轮、实际时间或表达质量的变化、重复使用。这些缺口保留在案例中，不用演示数据补齐。

下一次回访优先验证同一个任务：让用户选一条建议、修改采用、再讲一次；分别记录“判断是否正确”“是否实际采用”“重点是否仍被听懂”。若用户认可却不继续，应进一步区分建议不够可用、交互不清楚，还是当时没有重练需求。
