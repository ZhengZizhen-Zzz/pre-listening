# 验证什么，仍未证明什么

## 可复现的自动化验证

公开版本保留 302 项自动化测试，使用 Node.js 内置 test runner。测试主要使用合成会话、可控模型返回和临时目录；默认不消耗模型费用。

```bash
npm ci
npm test
npm run eval:validate
npm run test:release
```

| 风险 | 覆盖内容 |
| --- | --- |
| 引用与事实错误 | 原话不存在、页码错误、跨页冲突、数字变化、计划被改成成果 |
| Agent 失控 | 未知动作、非法参数、重复任务、循环上限、取消、只重试失败步骤 |
| 错判改善 | 同一录音改字、续录、不同材料、缺少计时、未完成录音不能伪造独立比较 |
| 录音与转写恢复 | 分段、时间偏移、终止状态、重复查询、避免重复提交 |
| 用户隔离 | 未登录拒绝、Origin / CSRF、反馈管理端隔离、跨用户任务访问拒绝 |
| 导入与交互 | 格式检查、大小限制、首屏预览、PPT 备注、讲稿分段、资源缓存 |

HTTP 合约测试使用可执行文件占位做转换器可用性探测，测试无效文件在进入转换前被拒绝；它不等于真实 LibreOffice 兼容性测试。安装完整转换器后的真实 PPT 验证需要另行执行。

## 公开模型评估输入

`evals/quality/cases.json` 中有 29 条合成案例，涵盖转述、口头补充、ASR 疑似错误、数字 / 方向 / 否定冲突、事实澄清与改稿保持。保留 development / holdout 标记用于追溯开发时的分组；案例已公开，不应把它们当作未来未见测试集。

- `eval:validate` 只校验输入结构，不是模型通过率。
- `run-quality.mjs --live` 才调用模型，需要明确案例 ID 与调用上限。
- 自动筛查检查可计算约束，人工复核仍需判断语义、建议价值与是否值得采用。
- 公开版本不包含真实用户片段、私人录音及未去标识的模型原始响应。

## 浏览器与真实模型链路验证

开发过程中使用合成材料和合成语音，走过真实网页录音、续录恢复、百炼转写、DeepSeek 诊断、改稿、出题与回答点评。功能验证使用真实服务；并非真人表现改善研究。

2026-10-13 的一次定向链路测量如下，仅保留不含私人数据的测量口径：

| 环节 | 此样本观察值 | 怎样理解 |
| --- | --- | --- |
| 40 页合成 PPTX 首屏 | 115 ms | 本地快速预览，不是全文件完成转换 |
| 同一材料完整预览 | 6.65 s | 受本机转换器、网络、字体和文件内容影响 |
| 约 70 秒合成录音转写 | 15.17 s | 两段录音恢复后的真实 ASR 路径 |
| 复盘诊断 | 9.17 s | 含模型与验证，非所有请求平均值 |
| 首个听众问题 | 75 ms | 本地生成的材料起始题，不是实时模型首 token 延迟 |
| 三题完整结果 | 2.96 s | 后台真实模型生成与校验 |

这些数字来自单次功能测试，不是 P50 / P95、服务承诺或商用容量指标。弱网、大体积文件、复杂 PPT 和不同移动系统需要独立验证。

## 公开版交付检查

- 安装后的依赖资源可由脚本重建，不依赖开发机缓存目录。
- 不配置模型密钥，仍能打开预设演练、查看复盘、模拟问题并采用示例改稿。
- 常规流程截图来自虚构校园预约案例；Agent 截图由实际组件加载合成输入，复用已有建议，未调用模型。真实模型执行证据单独提供。
- 发布检查排除常见密钥、私人文件类型、临时试用地址、个人路径和断链；其结果不替代人工审阅。

## 新增：真实反馈与 Agent 决策证据

- [一例匿名试用](USER-CASE.md)：两条建议被标为判断正确、愿意采用；尚无确认采用时间或独立下一轮。用户意愿与实际行为分开记录。
- [2026-10-14 Agent 实录](AGENT-TRACE.md)：4 种合成状态、实际 DeepSeek 与 MCP、共 7 次模型网络请求。未结束与时限内路径正常；两条压缩路径未通过引用校验，任务失败，未作为成功计数。
- `node scripts/record-goal-trace.mjs` 仅检查这 4 种输入；明确加 `--live` 才调用模型。它们不并入原有 29 条质量评估输入，也不把真实模型失败混在 302 项可控自动化测试的通过数里。

本次模型实录发现的压缩修复和保留约束问题列为待改进项；未以增加文档代替代码修复。详见记录中的失败路径分析。

## 下一阶段验收

1. 用真实设备覆盖手机锁屏 / 切后台 / 断网恢复，不把桌面模拟视为真机结论。
2. 分别测首个可用结果和完整完成时间，采集不同文件与网络条件的分布。
3. 记录建议正确性、采纳意愿、采用后是否重练，以及下一轮是否保持重点。
4. 做同材料、同任务的通用 AI 对照，验证整理上下文和完成练习的实际成本。

不以测试数量代替需求验证，不将预设示例当真实模型输出，不将工程防护宣称为消除了全部幻觉。
